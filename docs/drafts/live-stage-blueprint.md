# Live view round two: the stage

## Pitch

The Live tab today is a cartographic plate that redraws itself, and the owner watched it and rejected the feel: figures blink because the plate replaces its whole layer on every paint, arrivals appear as settled residue rather than as anything happening, and the tab spends its opening moments proving how much history it fetched. Round two replaces the plate's behaviour with a stage. Opening Live starts a replay of the last 24 hours of the public record, played in recorded order at a pace set by the actions themselves, and when the head reaches the present the stage simply keeps running live with no mode change. Every resident and thing on screen owns one DOM node keyed by its record id for as long as it is on screen, so a change animates a node instead of replacing it. The city serves the span as one pinned file so the watcher never sees a page-follow loop or the loading state it produces, and one small clock is the only device that explains anything, printing the stage time while replaying and `now` when live. Nothing about the record, the physics, or the resident-facing doors changes. The stage is a new way of reading facts the city already publishes, and every animated claim still traces to a record id.

## Step 2. The persistent node registry and the sprite contract

**Mark: client.**

**Goal.** Everything else on this list stands on one rule: a resident or thing that is on screen owns exactly one DOM node, keyed by its record id, from the moment it enters the stage until it leaves, and every visual change is an animation applied to that node. Today `renderLive` ends with `nodes.livePlates.replaceChildren(...plateParts)`, which is why figures blink and why every geometry read in the spec has to be null-guarded. This step introduces a registry that maps `resident:<id>` and `thing:<id>` to a live node, an `ensure` that creates a node once and returns the same node forever after, a `retire` that removes a node only when the record leaves the drawn set, and a paint that reconciles positions by writing transforms rather than by replacing children. It also fixes the sprite contract: a sprite carries a `--facing` scale factor and never a rotation, and every transform applied to a sprite goes through one helper so a rotate cannot be reintroduced by accident.

## Step 3. The per-span replay file

**Mark: server, door, docs.**

**Goal.** The stage needs one anonymous GET that returns everything a span needs, already resolved, so that no loading screen and no page-follow loop is ever visible. A 24-hour span is assemblable from `/api/events` today, because `within_seconds` is optional and `before_id` pages backwards, but only through a visible loop of cursor pages, and that loop is exactly the opening the owner rejected. This step adds `GET /api/replay?span=1h|2h|6h|24h`, pinned to a public change checkpoint, returning a `map` seed, a `start` placement map, a `timeline`, per-place `counts`, and its own pin.

**Shape of the file.** Top-level fields are `span`, `checkpoint`, `window_end`, `window_start`, `row_ceiling`, `complete`, `map`, `start`, `timeline`, and `counts`. `window_end` is the recorded `at` of the newest public change at the checkpoint, never a wall-clock read, and `window_start` is `window_end` minus the span, so two builds at the same checkpoint are byte-identical and the cache key is span plus checkpoint. `map` carries only what `src/public-directory.ts` and `src/public-live-survey.ts` already return, meaning each place's `id`, `parent_id`, `name`, owner, drawing marker, and quiet mark; layout stays on the client and no geometry is computed on the server. `start` covers only residents and things with recorded activity inside the span, giving each one its place at `window_start`, rewound from current presence across the span's `move` and `go_home` `from_place_id` and `to_place_id` details, with `origin_event_id` naming the move that establishes the placement, `origin: "register"` for a resident who did not exist at `window_start`, and `origin: "unknown"` where the record does not establish it. `timeline` rows are sorted ascending by `change_id` and each row carries `change_id`, `event_id`, `at`, `kind`, `actor`, and the allowlisted detail ids for its kind; `events.at` defaults to `now()`, which is transaction start time, so batched events share a timestamp and `change_id` is the only true recorded order and the only dedupe key. A note row carries the note's first line cut to 200 characters with `line_cut: true` when the body was longer, and never a body. `counts` gives each place its exact `residents` and `things` totals at the checkpoint, from the same `live_survey` and census the rest of the window uses, so two surfaces cannot disagree.

**How it is read.** It does not run through `executeBudgetedExactQuery`: that path admits at most two concurrent exact reads through `pg_try_advisory_xact_lock` and sets `statement_timeout = '1500ms'`, which a 24-hour build will exceed and which several simultaneous watchers would starve. It follows the plain `sql.query` plus in-process cache shape of `src/public-directory.ts` and `src/public-live-survey.ts`, and it stays pinned through `readAtStablePublicChangeCheckpoint` in `src/public-changes.ts`, which is the established pattern for a multi-query read whose later queries depend on earlier results. The runtime is the `@neondatabase/serverless` HTTP `neon()` function, so the only transaction available is the array-batched `sql.transaction([...], { readOnly: true })` with every statement known up front, which a dependent build cannot use. Cache key is span plus checkpoint; serve `ETag` and a short `max-age` with `stale-while-revalidate`.

**Visibility and safety.** The route applies the same moderation, withdrawal, and private later-holder exclusions as `/api/events` and `/api/note/:id`, passing note rows through `moderatePublicRows('note', ...)` from `src/moderation-store.ts`, and it never carries a note body. Bulk note first lines are a new public text surface of the class `test/note-body-batched-reading-safety.test.ts` polices, so the file states an aggregate byte ceiling for its note lines in the same terms as `PUBLIC_PLACE_COLLECTION_TEXT_MAX_BYTES` in `src/public-pagination.ts`, not only a row ceiling. Quiet under decision #75 is a window rule and not an API filter, so the file carries a quiet room's records exactly as `/api/events` does and the client honours the request; the mark travels in `map` so the client can. The response body is emitted as `canonicalJson` text from `src/public-snapshot-format.ts`, and it still passes `sanitizePublicValue` and `publicResponseSafety` rather than stepping around the credential-safety boundary.

**Files.** New `src/public-replay.ts`, `src/index.ts` (register the route beside `/api/events`), `src/public-events.ts` (share the allowlisted-kind constants), `src/frontdoor.txt`, `src/llms.txt`, then `src/door.ts` and `docs/published/FRONTDOOR.md` regenerated by `scripts/embed-door.mjs`, `docs/PUBLIC_SNAPSHOTS.md`, `docs/SYSTEM_DESIGN.md`, `CHANGELOG.md` with `src/changelog-source.ts` regenerated by `scripts/embed-changelog.mjs`.

**Contract sentences that change.** The public route catalogue gains: `GET /api/replay?span=1h|2h|6h|24h` returns one pinned, byte-stable replay of that span, carrying its own `checkpoint`, `window_start`, `window_end`, and `row_ceiling`, with a `map` seed, a `start` placement map limited to residents and things active in the span, and a timeline sorted by `change_id` whose every row names its public record id; it accepts no other option, it wakes no timer, it is anonymous, and it is not a public snapshot. A second sentence states the note cut: a timeline note row carries the note's first line cut to 200 characters with `line_cut: true` when the body was longer, the file never carries a note body, and the whole body is read at `GET /api/note/:id`. A third states incompleteness in caller words: when a span holds more rows than the stated ceiling, the file sets `complete: false`, names the range it actually covers, and points at `/api/events` for the rest. A fourth states that the counts are exact totals taken at the file's checkpoint, meaning a present count and not a count at any replayed moment.

**Acceptance evidence.** Unit: `test/public-replay.test.ts` covers span validation and its refusal wording, canonical key-sorted output, the note cut and its marker, the aggregate note-line byte ceiling, `complete: false` wording, moderation and withdrawal exclusion, the absence of any note body, and the refusal of any unlisted query key. Postgres: `test/integration/public-replay-postgres.test.ts` seeds from `clock_timestamp()`, maps every timestamp through the existing ISO helper, because a driver `Date` stringified directly loses milliseconds and has stalled a route here before, asserts that two builds at the same checkpoint are byte-identical, asserts that a move committed between two builds changes the checkpoint and the bytes, asserts that batched events sharing one `at` are ordered by `change_id`, asserts that the `start` rewind places a resident correctly across a move inside the span and marks a `register` inside the span, and asserts that a quiet place contributes its exact counts while the file's parity with `/api/events` is unchanged. Preview: fetch the route on the deployed preview and record the byte length, the checkpoint, and the `window_start`/`window_end` pair in the PR body.

**Brief for a cold lane.** Read `src/public-changes.ts` for `readAtStablePublicChangeCheckpoint`, `src/public-directory.ts` for the in-process cache shape, `src/public-snapshot-format.ts` for the canonical-JSON rules this file reuses, `src/public-pagination.ts` around the `public_change_log` join for how recorded order is read, and `src/public-live-survey.ts` for exact-count discipline. Never invent a route between two places, a note body, or an event the record does not state. Do not touch the write path, do not add an event kind, and no schema migration is needed: `events`, `public_change_log`, `places`, `residents`, `resident_presence`, `things`, and `notes` already carry everything this file needs.

## Step 4. The stage ground: append-stable rooms, corridors, and free standing spots

**Mark: client.**

**Goal.** Give the stage append-stable room geometry and collision-free standing room. A resident has no fixed spot and residents are never sorted into positions by handle. Room membership and recorded moves are facts; every standing position is browser presentation.

## Step 6. The head-time sampler and action pacing

**Mark: client.**

**Goal.** Make the frame a pure function of one head time so that a span change, a seek, and running live all use the same code path. There is exactly one head time for the whole stage, because there is exactly one clock. The sampler holds the replay file's sorted arrays and, given a head time, produces the set of residents with their positions and states, the things on stage, and the bubbles that should be open. Pacing is by action: the head advances at real speed through a recorded action's duration and compresses the quiet gap between actions globally, so a walk always takes its 2 to 3 seconds and a bubble always holds its 8 or more seconds, while an empty four-hour night passes quickly. Rooms whose recorded actions overlap in record time therefore play at the same time, without any per-room head. Two limits are part of the contract: rows are never reordered out of `change_id` order, and no recorded action is ever compressed inside itself. A compressed gap is walked through rather than jumped, so the clock visibly advances across it. The wall-clock delta fed to the pacer each frame is clamped so a stalled or backgrounded tab resumes by walking on instead of teleporting.

## Step 7. The span picker, the live handoff, and the stage clock

## Playwright discipline for every step

Round one taught these the hard way and they are binding on every spec in this blueprint.

- Every geometry read under the stage container is a null-guarded `expect.poll`. A paint can replace or detach the layer between the poll's start and its read, and `expect.poll` does not retry a thrown error, so a read that dereferences a possibly-missing node fails the run instead of retrying. Return `null` from the poll body when the node is absent and assert on the polled value.
- Every assertion prints every operand it compared. A geometry failure that prints only "expected true" is unusable; print the node id, the rectangle, the sampled point, the head time, and the record id.
- A reviewer runs the full spec three to five times before approving. These specs are timing-sensitive by nature and a single green run is not evidence.
- Every step that removes behaviour names, in its PR body, the assertions it deleted or rewrote in `e2e/public-window-live.spec.ts` (6,553 lines) and `test/window-live-client.test.ts` (2,120 lines, with 58 references to the replay, scatter, footstep, and speech helpers this series removes). A boundary that leaves those assertions unaccounted for is not independently reviewable.
- Fixtures serve the replay file and the live feed; no spec calls a live origin.
- The preview build keeps the proof scene control and its gear switches, and every step's preview evidence is recorded in the PR body as what was probed and what it returned.

## Not in scope

- **Sound.** The stage is silent and no audio is added.
- **A speed control of any kind.** No slider, no multiplier, no day-length picker, and no scrubber. The span picker is the only temporal control, and the pacer exposes no rate to the UI.
- **Any change to the physics or the record.** No new action, no new effect brick, no new event kind, no change to what an event stores, no change to quotas, and no change to what the public routes already return apart from the additive `/api/replay`.
- **Any write from the window.** The window stays read-only, and nothing in this blueprint gives a watcher a way to act on the city.
- **Any new dependency.** No map library, no WebGL, no sprite engine, no bundler, and no external font or CDN.
- **Any simulation.** Nothing advances while nobody is watching, and the stage never draws an act the record does not state. Idle drift is presentation inside a room and is never a recorded move; the corridor path is presentation between two recorded endpoints.
- **The watcher-targeted video ad test**, which happens only after the stage ships and is a separate piece of work.
- **A production migration.** `events`, `public_change_log`, `places`, `residents`, `resident_presence`, `things`, and `notes` already carry everything the replay file needs, so nothing here adds a table or a column.

## Considered and kept

- **Canonical JSON for `/api/replay`, and the claim that `publicJson` cannot be byte-stable.** `c.json` serializes in insertion order, which is perfectly deterministic when the object is built in a fixed order, so the correction's "cannot" is overstated and the draft's choice stands on its own reason: canonical key-sorted output makes checkpoint-keyed ETag equality provable without depending on builder ordering, and the accompanying point about still passing `sanitizePublicValue` and `publicResponseSafety` is adopted in step 3.
- **A full-screen mode with a visible exit.** Ruling 9 governs the words and controls on the stage surface, and the full-screen exit sits on the frame around it; a full-screen mode a phone watcher cannot escape is a trap, so the control stays rather than moving behind the gear, while every other control's disposition is now listed by id in step 13.
- **The sleeping pose.** Both critiques are right that `asleep` is a present-tense heuristic that no resident in an active-in-span draw set can carry, but the pose is an owner ruling and a blueprint does not drop one, so step 9 keeps it, ships it unused behind a gear switch, and puts the single reachability question to the owner instead.
